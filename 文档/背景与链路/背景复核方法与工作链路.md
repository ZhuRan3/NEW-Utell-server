# 背景复核方法与工作链路

本文件只记录通用复核方法、规范意识和可重复的工作方式；产品决策、技术选型、历史文件和具体文档均在新项目中重新建立。

## 复核方法

1. 先盘点目录、入口、构建文件、测试、契约和文档索引，确认研究范围。
2. 按“用户原文、需求材料、运行时事实、工程建议、待确认”分层，不把实现事实写成需求。
3. 采用渐进式阅读：入口规则 → 项目背景 → 当前 PRD → 相关架构/契约 → 当前任务所需原始文件。
4. 对材料、代码、页面行为和测试结果做交叉复核；发现冲突就登记，不静默合并。
5. 每个新结论都关联证据、影响、回滚条件和后续动作，保证新会话可复盘。
6. 每次复核都先生成“项目驾驶舱”摘要，再按测试站格式登记证据；专业名词保留英文并配白话教学，状态区分 `已证实`、`待证据`、`待决策`、`待开发`。

## 可复用工作链路

```text
范围盘点
  -> 来源分层与冲突登记
  -> 需求原文和 Q&A 对齐
  -> 架构边界与公开契约
  -> 脱敏 fixtures / mock / fake
  -> 可重复场景与故障注入
  -> 单测、契约测、集成和 staging 证据
  -> 发布门禁、回滚和变更记录
  -> 驾驶舱摘要、术语学习和会话交接
```

## 新仓库原则

- 只以当前仓库中的 PRD 和后续新 Q&A 为产品输入。
- 不从外部工程复制默认技术栈、目录、协议、数据模型或产品决策。
- 所有需求、选择题、原文回答、细分 PRD 和技术选型从本仓库重新建立，中文说明优先。
- 先确定边界和验收，再实现；先建 harness，再进行跨端联调和部署演练。
