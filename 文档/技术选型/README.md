## 决策包必填字段

1. 问题定义：要解决的能力与场景、范围与非范围、最晚决定时间。
2. 硬约束：来自 PRD 与 Q&A 的不可交易条件；不满足硬约束的候选直接淘汰。
3. 候选方案：不少于两个真实可行候选，写明准确名称、版本、许可证和官方来源。
4. 证据：区分官方资料（E1）、环境核实（E2）、可复现 Spike（E3）、真实负载（E4）；禁止仅凭 AI 记忆下结论。
5. 候选矩阵：同一组维度对比，未知项留空或标“待验证”，禁止编造分数。
6. 失败、迁移和退出路线。
7. AI 建议与开发者决定分开记录；开发者决定包含理由、接受的剩余风险和重审条件。

## 规则

- 决策包是“待确认”状态的文档；批准后才允许写入架构基线并解锁对应实现任务。
- 高风险未知必须安排 Spike，Spike 结果回写决策包。
- 技术选型变更按 `开发规则规范/01-需求对齐与Q&A规范.md` 走 Q&A 记录。
