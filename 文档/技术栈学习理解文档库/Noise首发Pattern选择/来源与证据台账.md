# Noise 首发 Pattern 选择：来源与证据台账

> 调研日期：2026-08-24
> 证据原则：官方规范/实现文档用于定义事实；论坛与 issue 用于观察真实工程取舍；项目文档用于约束 NEW-Utell 的本地语境。

## 官方规范与协议文档（E1）

| 来源 | 用于支撑的结论 |
|---|---|
| [Noise Protocol Framework](https://noiseprotocol.org/noise.html) | `e/s/ee/es/se/ss` 符号；XX 与 IK 脚本；协议名格式；XX/IK 身份隐藏等级；0-RTT；Noise Pipes/XXfallback；rekey 由应用决定 |
| [WireGuard Protocol](https://www.wireguard.com/protocol/) | 真实系统使用 `Noise_IKpsk2_25519_ChaChaPoly_BLAKE2s` 的例子；IK 适用于配置阶段已可靠分发静态公钥的场景；两条握手消息与密钥轮换/重放处理 |
| [RFC 7748](https://www.rfc-editor.org/rfc/rfc7748) | X25519/Curve25519 密钥交换的标准背景 |
| [RFC 8439](https://www.rfc-editor.org/rfc/rfc8439) | ChaCha20-Poly1305 AEAD 的标准背景 |

## 证据限制与待补实测

- 官方规范说明安全属性，不提供 NEW-Utell 网络环境下的 P95 握手耗时。
- WireGuard 的 IK 经验不能直接证明 NEW-Utell 适合 IK，因为 WireGuard 的公钥是配置前置条件，而 NEW-Utell 首次配对依赖扫码和用户确认。
- `snow` README 明确提示未正式审计，且不实现 `fallback` modifier；不能未经验证就承诺 Noise Pipes 互操作。
- libp2p 的选择是工程经验，不是“XX 永远比 IK 安全”的证明。
- Swift 侧候选库、许可证、iOS 17 构建和跨语言向量已通过本项目 Spike；Connector 共同验收和真机生命周期仍需补证据。
