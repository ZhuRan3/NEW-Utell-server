# 文档生命周期与中文规范

## 真源与交付物

- Markdown 是唯一可维护真源；PRD、架构、Q&A 和测试说明都以 Markdown 保存。
- 需要审阅的 DOCX/PDF 只能作为生成物，必须注明来源版本，不反向手改。
- 临时转换文件、下载缓存、密钥、日志和构建产物不得提交。

## 目录和命名

- 面向人的说明、Q&A、决策和工作记录优先使用中文文件名。
- 协议字段、代码符号、命令、错误码和外部包名保留英文原文。
- 文件名使用稳定语义，不把日期或版本塞进每个真源文件名；版本写在文档头部和变更记录。
- 新增页面级或模块级细节时单独建文档，不把像素规格堆进总 PRD。

## 变更流程

```text
提出变更 -> Q&A 记录 -> 用户确认/标记待确认 -> 更新真源
  -> 更新契约与场景 -> 生成证据 -> 变更记录
```

删除文档前先确认是否为当前真源；历史结论只能归档或标记变更，不直接抹除。
